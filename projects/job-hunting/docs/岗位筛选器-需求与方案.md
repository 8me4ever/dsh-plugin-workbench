# 岗位筛选器(Job Radar)需求与方案

> 状态:✅ 已碰撞定稿 · 待开发
> 日期:2026-08-20(首版)
> 仓库:job-hunting · docs/

## 1. 产品定位

**一句话:** 把「每天刷 3 个招聘网站」变成「打开一个仪表盘,看已按我的标准筛好的岗位清单」。

**解决的核心痛点:**
- 信息分散:要同时开多个招聘平台
- 重复岗位多:同一职位多个渠道重复出现
- JD 良莠不齐:薪资虚标、挂职位不招人
- 错过机会:合适岗位出现在视线之外

## 3. 核心流程

```
多源采集 → 清洗标准化 → 硬性过滤 → LLM 匹配打分 → 排序分组 → 仪表盘展示 → 投递追踪 → 反馈校准画像
```

## 4. 功能模块

### 4.1 岗位雷达(采集引擎)
- 多源定时抓取:聚合订阅源(RSSHub 等)→ V1;招聘平台 → V2
- 增量采集、去重(同岗位多渠道只保留一条)、失效检测(岗位下架标记)

### 4.2 JD 智能解析
- LLM 将非结构化 JD 抽成结构化字段:薪资范围、经验年限、技能栈、学历、福利、远程/通勤

### 4.3 匹配引擎
- 简历画像 vs JD 打分
- 硬性条件一票否决(城市、薪资下限、经验、学历、必须技能)
- 软性维度加权计分 → 输出 S/A/B/C 分级

### 4.4 公司情报
- 自动补全公司规模、融资阶段、成立年限、口碑
- 过滤皮包公司、常年挂职位的「僵尸岗位」

### 4.5 投递管理
- 已投/待投/意向追踪,自动识别重复岗位,记录投递日期与反馈

### 4.6 反馈闭环
- 对岗位标记「不合适」的原因 → 反哺校准画像权重,越用越准

## 5. 打分模型(画像参数化,方向待定后填入)

### 5.1 硬性过滤(一票否决)
| 条件 | 说明 |
|---|---|
| 城市 | 北京 / 深圳(可扩展) |
| 薪资下限 | 待定 |
| 经验年限 | 待定 |
| 学历 | 待定 |
| 必须技能 | 待定(岗位方向确定后填写) |

### 5.2 软性评分(加权)
| 维度 | 权重 | 说明 |
|---|---|---|
| 技能匹配度 | 40% | JD 技能栈与画像重叠度 |
| 经验契合 | 20% | 年限、职级匹配 |
| 公司实力 | 15% | 规模、融资阶段、口碑 |
| JD 新鲜度 | 10% | 发布时间越近分越高,防僵尸岗 |
| 通勤/远程 | 10% | 通勤时长、是否远程 |
| 其他 | 5% | 福利、加班文化等 |

### 5.3 输出分级
- **S 级** 强匹配 → 立即投
- **A 级** 可投
- **B 级** 观察
- **C 级** 放弃

## 6. 数据源规划

| 阶段 | 数据源 | 采集方式 |
|---|---|---|
| V1 | RSSHub / 官方聚合源 | 低风险,合规,优先 |
| V1 | 猎聘、智联、前程无忧 | 常规抓取,🟡 可选 |
| V2 | BOSS直聘 | 浏览器半自动(登录态),不硬刚反爬 |
| V2 | 公司官网/内推 | 精准合规,补充 |

## 7. 技术方案选型

| 方案 | 原理 | 结论 |
|---|---|---|
| A 纯爬虫 | requests/Playwright 硬抓 | ❌ 不推荐:反爬强、维护高、法律风险 |
| B 爬虫+LLM | 抓原始数据 + LLM 解析打分 | 🟡 V1-V2 主力 |
| C 官方API/聚合 | 猎聘API、RSSHub | ✅ V0-V1 优先 |
| D 浏览器半自动 | 登录态 + 浏览器自动化 | 🟡 V2 补充 |

## 8. 风险与合规

- **法律合规**:遵守 robots.txt 与平台用户协议,仅限个人学习使用;不采集个人敏感信息
- **技术风险**:IP 封禁、验证码、登录态过期 → 用半自动方案绕过而非对抗
- **数据质量**:JD 水分大 → 新鲜度检测 + 公司情报过滤
- **隐私底线**:简历与画像数据只存本地/私有仓库,不推送公开渠道

## 9. 路线图

| 阶段 | 内容 | 时间 |
|---|---|---|
| V0 | 手动粘贴 JD → LLM 解析打分 → 输出清单,验证筛选逻辑 | 本周 |
| V1 | 接入聚合源,定时抓取 → 自动入库 → 本地仪表盘 | 1-2 周 |
| V2 | 浏览器半自动采集 BOSS,公司情报 + 投递追踪 | 3-4 周 |
| V3 | 反馈闭环自动校准画像,推送渠道扩展(邮件/企业微信) | 1-2 月 |
